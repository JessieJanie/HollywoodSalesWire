Name filter is your keyword list (Productions/Pictures/Films/Studios/Media/Entertainment/Post/VFX/Television) with word boundaries. Expect some non-film noise ("NOVA WELLNESS STUDIOS") — your pipeline should do the second-pass relevance judgment.
Dedupe is by official registry ID, so an entity never repeats across polls.
Use publishedAt for your 10-day freshness filter, not filingDate (see the TX note below).
Phase 1 source status — read this part carefully
Source	Status	Notes
NY	✅ live	NY Dept of State open-data feed, updated daily. Filing date, entity type, registered agent where the registry publishes one.
TX	✅ live	Official Texas Comptroller franchise-tax registrations (the TX SOS itself only sells records behind a paywall). Can lag the SOS filing by a few days. filingDate is the declared "responsibility beginning" date and is occasionally future-dated — that's in the record itself; publishedAt reflects when the registration actually became public. No registered agent in this dataset.
CA	❌ blocked	bizfile is behind an Imperva bot wall. CA offers an official API (CALICO) that needs an account signup — Karilyn, that's a to-do for us at calicodev.sos.ca.gov if CA matters enough.
GA	❌ blocked	eCorp sits behind a Cloudflare challenge that defeats even browser rendering.
NM	❌ blocked	The portal drops datacenter traffic and exposes no public searchable formation feed.
CA/GA/NM are known coverage gaps, not failures, so the response reports crawl.status: "ok" when NY and TX both succeed — degradedSources is reserved for a live source that breaks (exactly like studio-jobs when a board fails). Every crawl probes the three walled registries anyway; if a wall ever comes down our alarms fire and we add the adapter.
